# Видео → поза → GMR → G1

Модули находятся в `video_teleop/`. Команды выполняются из корня `fast_teleop`.
Веса зрения находятся в `models/`, временные файлы — в `.cache/`.

```bash
./uv sync --locked
./uv run python -m video_teleop.pose_stream --download-models
./uv run python -m video_teleop.pose_stream --source 0 --retarget --udp 127.0.0.1:9870
```

Вместо камеры можно указать видеофайл или RTSP/HTTP URL. `--no-display`
выключает отрисовку; `--cpu-threads 1 --profile` помогает измерить нагрузку.
Выбор человека — TAB, выход — Q/Esc. Одно окно показывает полный видеокадр и скелет человека.
Отрисовка робота убрана; ретаргетинг и UDP продолжают работать.

YOLO выбирает человека; автоматического кропа нет. Easy-ViTPose,
MediaPipe Pose Heavy и ладони обрабатывают полный кадр параллельно. Поддерживается
VideoPose3D через `--pose-backend videopose3d`. GMR переводит наблюдаемую позу
в суставы G1. Отсутствующие части и неполные цепочки ног исключаются масками.
Лицо не рисуется. `--no-palms` выключает дополнительное определение ладоней.

Один UDP-отправитель обслуживает два режима нового WBC-деплоя:
`R2+A` — всё тело, `R2+X` — только руки. Область камерных целей выбирается
контроллером; WBC сохраняет управление ногами и корпусом для баланса.
При ошибке открытия камеры/файла или пустом входе исходная WBC-стойка
передаётся непрерывно на 50 Гц ещё до загрузки моделей. Недоступный источник
проверяется повторно; отключившаяся камера переподключается. Конец видео
переводит отправитель в исходную стойку без повторного проигрывания.
Отсутствие изображения не отправляет `stopped`; это сообщение остаётся
только для явного выхода (Q/Esc/Ctrl+C). При `stopped`, таймауте и отсутствии
первых кадров контроллер остаётся в Teleop/TeleopArms: WBC держит баланс
с исходной стойкой и ждёт данные сколько потребуется. После запуска или
перезапуска отправителя телеоп возобновляется плавно, без повторного нажатия
кнопки режима. Ошибка запуска/инференса WBC по-прежнему переводит в Walk
с нулевой скоростью; тогда движение разрешается после 0,2 с стиков в центре.
Лимит суставной reference теперь 5 рад/с (`--max-joint-speed`); в деплое
действует соответствующий `reference_max_speed: 5.0`.
При потере человека отправляется явная исходная WBC-стойка; повторы позы
сохраняют индекс кадра для корректной интерполяции.
