# WBC reference and deployment audit

This audit covers the G1 `wbc_tracking_params_v1` bundle deployed here, the camera/TRACE transport, the local ROS2 deployment source, and the local `wbc-mjlab` training loader/kinematics. It is not a certification of arbitrary generated motions or a comparison with the private data used to train the checkpoint.

## Corrected mismatches and removed software restrictions

1. **Pelvis velocity instead of torso velocity.** The actor's `ref_base_*` names refer to `torso_link`, not the free root. Previously TRACE sent only root translation velocity. It omitted the torso offset contribution and waist rotation. Generated packets now contain the exact torso link-origin position, orientation, linear velocity and angular velocity, computed by the same FK routine as training NPZ export.
2. **Missing vertical velocity.** Previously WBC replaced Z velocity with a derivative of smoothed/clamped height; an XY-norm condition could suppress the entire generated velocity branch on purely vertical motions. All three reference linear components now reach the actor, including jumps with zero XY translation.
3. **Angular velocity derived at the wrong stage.** Previously it came from two filtered orientations at controller wall times. Its value depended on filter lag, entry blending and UDP sampling. Generated motion now supplies the training-derived world angular velocity; the receiver converts it into the reference torso frame.
4. **Different torso kinematic tree.** The former 35 mm offset followed by a roll-dependent 9 mm offset came from a GMR asset. Training G1 places the full `[-0.0039635, 0, 0.044]` offset before waist roll/pitch. Both the generated FK and native legacy/camera fallback now use the training chain.
5. **Reference EMA of 0.08 s.** Removed from WBC. It delayed the joints and orientation relative to source position/velocities and the dataset.
6. **Joint reference cap of 5 rad/s.** Removed from WBC. It distorted fast motions without retiming the other reference terms. The separate camera GMR output cap is disabled by default (`--max-joint-speed 0`); it remains an explicit optional sender setting.
7. **Two-second measured-to-reference blend.** Removed from WBC. It consumed/distorted the beginning of a playing clip while its source clock continued normally. TRACE's initial pose comes from the reference snapshot; WBC now receives the actual clip from its first usable sample.
8. **Torso height clamp of 0.4–1.2 m.** Removed. Crouches, floor motions and jumps retain their reference height. The startup `wbc_base_height` setting is also checked only for finiteness, without the former 0.4–1.3 m configuration restriction.
9. **Torso vertical slew cap of 0.5 m/s.** Removed along with the separate height filter.
10. **Reference angular-speed cap of 3 rad/s.** Removed.
11. **Motor-position clipping after residual inference.** Removed for WBC. The actor's exact trained output is `q_reference + action_scale * raw_action`; clipping it to GMR joint ranges changed learned balance corrections. The raw previous action still goes into the next observation.
12. **Additional PD-torque target rewriting at 98% of catalog peak.** Disabled in Teleop and TeleopArms. This software target rewrite is separate from physical actuator torque saturation and the simulator's motor model. Other FSM policies retain their own settings. `pd_torque_clipping.enabled` remains an explicit configurable option.
13. **Wholebody inclination cutoff at 1 rad (~57.3°).** Disabled in Teleop/TeleopArms through their existing per-state `enable_bad_orientation_passive: false`. It would otherwise interrupt floor/large-lean movements irrespective of what the policy was trained to execute.
14. **Packet amplitude guards (root Z 0.1–2 m, joint magnitude 10 rad, generated root speed 15 m/s).** Removed. Finite values, named array dimensions and a valid quaternion remain required. A magnitude guard on measured joint velocity at 35 rad/s was also removed; invalid/nonfinite measurements are still rejected.
15. **Camera base translation was discarded.** A complete observed base now contributes root position derivatives and rotation/waist derivatives to native torso kinematics. Missing base/legs retain the explicit stance behavior, rather than inventing unobserved motion.
16. **Default generation boundary height mismatch.** The old no-camera snapshot used a hardcoded 0.7842 m pelvis, independently of the configured 0.8382 m torso height. It now derives the pelvis height from `wbc_base_height - 0.044` for the training torso chain. Tracked bases keep their supplied pose.
17. **Potential playback stall during FK preparation.** Full kinematics and the web preview are prepared/cached in a worker thread before playback, outside the asynchronous 50 Hz output loop.

The obsolete `transition_duration_s`, `reference_smoothing_s`, `reference_max_speed`, and `max_joint_speed` deployment settings have been removed. Nonzero legacy values fail configuration validation rather than silently claiming to change direct WBC playback. `--reference-smoothing 0` remains a compatibility no-op; nonzero values fail explicitly.

## Verified matching parts

The source model files, joint order, default joint positions, per-joint action scales, KP and KD are unchanged. The actor receives 132 observations in the exported order, with 39 reference features, 29 previous raw actions and no actor history/state estimator. Reference residual actions do not receive walking/SONIC offsets. The trained policy step is 0.02 s (50 Hz).

NPZ export and live playback share the training G1 kinematic tree, quaternion order WXYZ, metres/radians, central finite differences with one-sided endpoints, and **world-frame velocities at link origins**. Velocity and gravity observations are expressed in the **reference torso frame**. Root XY/initial heading alignment is a rigid planar transformation; it does not alter these actor features. Native interpolation is still applied to timed packets.

## Remaining constraints and limits of the system

- **The checkpoint defines the capability.** A model's ability on its training motions does not establish coverage of every TRACE output. Valid shape/kinematics does not prove contact feasibility or dynamic trackability. No checkpoint retraining or weight changes were made.
- **This checkpoint observes a local 39-D motion reference.** It has no absolute XY/root-position or heading-error observation, no future trajectory window, no contact labels, and no joint reference velocity input. Those inputs cannot be added without a compatible model export/retraining. Horizontal drift and an arbitrary full-world path are not constrained directly.
- **50 Hz control and temporal sampling.** TRACE creates a complete motion at 20 Hz; the bridge interpolates it at 50 Hz. Interpolation cannot recover missing high-frequency content. The receiver requires two frames and retains an adaptive interpolation delay: normally about 40 ms for a stable 50 Hz sender, more with jitter or a low-FPS camera. It does not extrapolate beyond the latest sample.
- **A packet timeout still selects the initial reference.** `stream_timeout_s` defaults to 1 s; teleop itself waits indefinitely and the actor/history keeps running. A reference source change or loss can now change the goal immediately because deployment smoothing was intentionally removed. At generated-clip end the sender holds the final pose and sets its velocities to zero.
- **Arms is intentionally partial.** R2+X replaces the first 15 joint goals, root motion and torso goals with the WBC stance. Use **R2+A / Teleop** for wholebody generated trajectories. WBC still controls all 29 joints for balance in Arms.
- **Visibility masks still apply to video.** Unobserved joints fall back to the policy stance. A partially observed leg chain is excluded as a whole; root tracking requires both complete leg chains. This preserves the user's requirement not to synthesize missing parts.
- **Camera retargeting retains mechanical IK ranges and pose-estimator processing.** GMR's joint ranges, frozen unobserved DoFs, palm range/quality checks and human-to-robot scaling are part of retargeting. The optional VideoPose3D backend also retains its own temporal estimator/0.4-new + 0.6-previous position smoothing. These do not process TRACE motion.
- **TRACE retains its own generation contract.** The local planner predicts at most 512 frames at 20 Hz. The current worker uses `generator_boundary.pt`, a snapshot for both endpoints, 8 boundary frames, CFG 2.5, root/joint low-pass cutoffs 3/4 Hz (order 4), and optional heel/toe contact refinement. These steps define the generated and saved reference itself; no additional deployment smoothing is applied. Preview the saved result to see what the generator actually produced.
- **Physical motor and simulation constraints remain.** Torque–speed envelopes, maximum effort, contact/friction, joint mechanics, latency and available CPU cannot be removed by forwarding a larger command. The bundled Unitree MuJoCo dynamics is not identical to the training actuator model: e.g. its XML hip/knee/ankle motor peaks are 88/139/50 N·m, whereas the training Unitree presets/previous software caps use 83.3/131/63.8 N·m. It also uses fixed joint damping/armature/friction; training implements Unitree torque–speed/friction and reflected inertia. The external `unitree_mujoco` model on a user's machine must be checked separately.
- **Data validity and explicit stop remain.** Invalid IMU quaternions/nonfinite state, LowState freshness (default 80 ms), malformed packets, wrong robot/names, duplicate/out-of-order source frames, and emergency Passive are still checked. Real receiver/model errors retain Walk recovery. These do not cap valid reference amplitudes.
- **The web preview is kinematic.** It shows the generated G1 reference, not the robot's policy rollout. Its pause/seek/speed controls never alter the selected deployment source. "Send to deployment" is a separate action.

## Validation

- Real native ONNX: all 39 reference features match the training-export computation (absolute tolerance 2e-6), including nonzero waist motion, root angular speed above 3 rad/s, height outside 0.4–1.2 m, joint motion above 5 rad/s, and vertical velocity.
- Real native ONNX: output equals the independently invoked raw model's `q_ref + scale * action`, including previous-action observations, without joint/PD-target clipping.
- Five existing generated clips played through the bridge, native packet interpolator and WBC actor in closed-loop local MuJoCo. No falls or rejected packets; peak body tilt 5.5–13.2 degrees; joint tracking RMSE 0.077–0.105 rad. The clip requested as a jump was evaluated as the trajectory that TRACE actually generated, without asserting a particular jump height.
- Reference export is still tested with the actual local training NPZ reader/stack loader and isolated MotionLoader implementation. No training job or physical robot run was started.

Detailed local numerical results are in `.cache/performance/wbc-direct-generated-mujoco.json`; the reproducible contract tests are `motion_teleop/tests/test_native.py`.
