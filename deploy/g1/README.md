# G1 deploy: traj_loco + WBC

Ходьба и телеоп используют две политики из пользовательского `policy_deployment_ros2`:

- `policies/traj_loco`: ходьба с DDS-геймпада. Декодер, `stand_adjust` и
  оценка скорости — единый комплект. Нейросетевого генератора GR00T нет:
  траектория из 10 точек строится интегрированием команды скорости.
- `policies/wbc`: отслеживание позы G1 после GMR с балансом всего тела.
  Доступны WHB и Arms. Пальцы кистей не управляются.

Скопированные веса и исходные параметры не изменены; контрольные суммы
находятся в `policies/SOURCE.json`. Соседний репозиторий для запуска не нужен.
Отдельно добавлен минимальный комплект GetUp из Punch_mode.
SONIC, GrootCamera, прежние походки GR00T, Velocity и Mimic удалены.

## Сборка

Из корня `fast_teleop`, после установки Unitree SDK2 и C++ зависимостей:

```bash
cmake -S deploy/g1 -B deploy/g1/build -DCMAKE_BUILD_TYPE=Release
cmake --build deploy/g1/build -j2
deploy/g1/build/g1_ctrl --check-config
```

Сабмодули Unitree RL Lab и GR00T не нужны. Минимальная обвязка FSM/DDS
и joystick DSL включены обычными исходниками в `third_party/unitree_deploy`
с исходной Apache-2.0 лицензией. CMake собирает напрямую `src/main.cpp`.
Для SDK2 используется установленный пакет `find_package(unitree_sdk2)`.

Зависимости: C++17, Eigen3, yaml-cpp, nlohmann-json, Unitree SDK2,
Boost program_options, spdlog/fmt, ONNX Runtime. ROS2, CUDA и TensorRT не нужны.
CMake автоматически выбирает CPU ONNX Runtime:

- x86-64: включённый `third_party/onnxruntime-linux-x64-1.22.0`;
- ARM64 / Jetson: включённый `third_party/onnxruntime-linux-aarch64-1.23.2`.

ELF-архитектура библиотеки проверяется. Свой дистрибутив задаётся через
`-DONNXRUNTIME_ROOT=/path`; `-UONNXRUNTIME_ROOT` возвращает автовыбор.
Для другой архитектуры используйте новый каталог сборки.
Это относится к C++ контроллеру; Python/MediaPipe на Jetson требует отдельного окружения.

## Запуск

Для текущего unitree_mujoco, DDS domain 1:

```bash
deploy/g1/build/g1_ctrl -n lo --domain 1
```

Во втором терминале камера:

```bash
./uv run python -m video_teleop.pose_stream --source 0 --retarget \
  --udp 127.0.0.1:9870 --no-display
```

Без `--no-display` показывается одно окно с полным видеокадром и скелетом человека, без отрисовки робота.
`--retarget` без `--udp` включает только просмотр, без передачи в деплой.
Для файла замените `--source 0` на путь к видео.
На физическом G1 задаются его DDS-интерфейс и domain; `lo` здесь — симулятор.

## FSM и кнопки

Логика перенесена из локального `policy_deployment_ros2`,
`robots/g1_29dof_ros2_deploy/src/ros2_policy_deploy.cpp`.
Входные данные здесь передаются через Unitree DDS и UDP камеры.

- `L2+Up`: FixStand из любого положения, включая лёжа. Политика отключается,
  первая точка `qs[0]` заменяется измеренными суставами. Далее выполняется
  линейная интерполяция по `ts/qs` с собственными `kp/kd`.
  Поза и коэффициенты скопированы из исходного `FSM.FixStand`.
  После завершения удерживается последняя точка; автоматического WBC нет.
- `R1+X`: Walk. Левый стик — движение, правый — поворот,
  центрирование тормозит. Удерживать L1 не требуется.
- `R1+Y`: Run на той же TrajLoco: вперёд до предела из `FSM.Run.velocity_limits.forward`.
- Повторное `L2+Up` из FixStand: GetUp → Walk.
- `L1+Up`: Idle политики traj_loco.
- `R2+A`: Teleop через WBC, всё наблюдаемое тело.
- `R2+X`: TeleopArms, руки и запястья из камеры.
- `L2+B`: Passive: политика отключена, `kp=0`, `kd` берётся из FSM.Passive.

Переходы определяются графом `transitions`. Дополнительных ограничений входа
по ошибке суставов, скорости моторов 0,5/5 рад/с и ожиданию `FixStand ready` нет.
При каждом входе в состояние политики сбрасываются её история и последнее
действие; для VQ также сбрасываются траектория и оценка перемещения.
Фиксированные позы могут иметь `auto_transition`, который выполняется
после последней точки `ts`; целевой переход должен быть объявлен в графе.

`enable_bad_orientation_passive` включает автоматический возврат активной
политики в Passive при наклоне выше `bad_orientation_limit_rad`.
У телеопа срабатывание этой проверки считается сбоем телеопа и направляет
в Walk; у остальных политик остаётся Passive. Общий флаг и порог находятся в `deploy.yaml`, отдельное состояние может их
переопределить. У Walk и Idle флаг `false`, как у исходного Walking;
у Teleop и TeleopArms — `true`. Для запуска политики лёжа задайте её флагу
`false`. Это разрешает инференс, но не добавляет модели навык подъёма.
Passive и FixStand не проверяют наклон независимо от общего флага.
FixStand удерживает суставные цели, но не обеспечивает динамический баланс:
в проверке свободного G1 после положения рук перед собой чистый PD
теряет равновесие. Для стабилизации применяется политика Walk/Idle или WBC;
автоматический запуск такой политики в FixStand намеренно не выполняется.

В Arms ноги и корпус не получают камерных целей, но WBC управляет ими для
баланса. Неполные цепочки ног исключаются из reference. Формула WBC:
`reference_q + scale * action`. В Teleop/TeleopArms программная обрезка
позиции и PD-момента отключена; физические лимиты моторов/симулятора сохраняются.

Сохранены проверка корректности IMU/суставов, приоритет Passive, watchdog LowState и защита от второго
публикатора команд. DDS передаёт IMU и суставы одним LowState; его допустимый
возраст задаёт `max_sensor_age_s` (по умолчанию 0,08 с).

Скорости задаются в `FSM.Walk.velocity_limits` и `FSM.Run.velocity_limits`
в м/с. Walk: вперёд 1,5, назад 0,5, вбок ±1. Run: вперёд по `velocity_limits.forward`, назад 0,5,
вбок ±1, суммарная линейная скорость ограничена `velocity_limits.planar`. Скорость поворота и ускорения
сохранены из исходной TrajLoco. Ограничивается команда планировщика;
фактическое достижение выбранной скорости моделью не гарантируется. Внутреннее ограничение
ошибки траектории для Run также увеличено, чтобы старый предел 5 м/с не мешал.

GetUp использует отдельный `getup.onnx` из исходного Punch_mode и только
два исходных CSV (`t061`, кадры 212…345; `t067`, кадры 288…458).
Выбор по projected gravity X < -0,1, выравнивание yaw и командный вектор
73 элементов перенесены из ветки `get_up` ROS2-деплоя. Инференс — 50 Гц. Параметры позы, kp/kd, офсеты, выбор take и сборка
наблюдений сверены с исходником. На выход VQ не применяются узкие GMR-лимиты
из ретаргетинга: они искажали совместное движение тазобедренных суставов
и коленей. Сохранён исходный `clip(raw_action, -20, 20)` и нулевые запястья.
Проверка наклона у GetUp отключена; после последнего кадра выполняется
`return_state: Walk`. Стики не вмешиваются в подъём. `L2+B` прерывает в Passive,
`L2+Up` — возвращает в FixStand. Модели ударов и боевой ходьбы не добавлены.

## Конфигурация

- `config/config.yaml`: единственный FSM, кнопки, FixStand, пути политик и
  флаги каждого состояния. 
- `config/deploy.yaml`: `initial_state`, общие настройки проверки наклона,
  возраст LowState, частота 50 Гц, UDP, таймауты и сглаживание камеры.
- `config/robot_defaults.yaml`: исходные параметры из ROS2-деплоя,
  включая `pd_torque_clipping` с долей 0,98 от максимального момента.
- `policies/traj_loco/config.yaml`: исходный контракт VQ и планировщик скорости.
- `policies/wbc/params/config.yaml`: исходный контракт WBC.
- `config/initial_pose.json`: явная WBC-стойка камеры при отсутствии человека.

`--config` переопределяет FSM, `--deploy` — общие параметры.
`--check-config` проверяет конфигурацию и обе модели до инициализации DDS.
Модели загружаются заранее. ROS2-зависимостей и дополнительных политик нет.
Камера сохраняет плавный переход reference от измеренной позы и непрерывную
интерполяцию UDP-поз; это адаптация внешнего reference для видео.

## Поток камеры

Формат `gmr-g1-v1`, UDP 9870, сохранён. Отправитель работает на 50 Гц независимо
от FPS распознавания. Повторы сохраняют индекс исходной позы и не создают
ложные кадры. Приёмник интерполирует предыдущую и текущую завершённые позы,
удерживая последнюю цель без экстраполяции. Разрыв видимости не соединяет две
несвязанные позы. Неполная цепочка ноги полностью исключается из камерных целей.

Недоступная камера/видеозапись не завершает отправитель: он передаёт
исходную стойку на 50 Гц и повторяет открытие источника. Даже модели зрения
не нужны для такого fallback. Конец файла оставляет исходную стойку, без
автоматического повторения видео. Явный выход по-прежнему отправляет `stopped`.

Краткий провал трекинга удерживает цель; затем отправитель передаёт явную
исходную WBC-стойку. До первых двух кадров WBC также работает с исходной целью.
Отсутствие первых кадров, прекращение связи и явный `stopped` не переключают
Teleop/TeleopArms: WBC продолжает работать на 50 Гц и держит баланс с исходной
стойкой. Ожидание не ограничено по времени. `stream_timeout_s` определяет,
когда устаревшая поза заменяется исходной стойкой; это не таймаут
выхода из политики. Удалён прежний `startup_timeout_s`. После появления двух
новых кадров, в том числе после перезапуска отправителя, телеоп возобновляется
автоматически, без фильтра и ограничителя скорости reference.
История WBC при ожидании и возобновлении не сбрасывается.

Ошибка открытия UDP или инференса WBC по-прежнему ведёт
в Walk (`failure_state: Walk`), без промежуточного Passive. В Walk сначала
нулевая команда скорости: для возобновления движения стики должны побыть
в центре 0,2 секунды. После такого сбоя для возврата в телеоп снова нажмите
R2+A / R2+X. Аварийная кнопка L2+B, потеря LowState и некорректные данные
IMU/суставов сохраняют переход в Passive. Ошибки самой политики Walk
не маскируются повторным перезапуском.

WBC reference передаётся напрямую: удалены EMA, лимит 5 рад/с, подмешивание
первых двух секунд, лимит высоты 0,4–1,2 м, вертикальной скорости 0,5 м/с и
угловой скорости 3 рад/с. Для исходного видео `--max-joint-speed 0` отключает
дополнительный лимит GMR (по умолчанию). Механические диапазоны IK сохраняются.

Полный reference от TRACE включает позу и скорости `torso_link`, рассчитанные
той же кинематикой, что экспорт NPZ для обучения. WBC использует все три
компоненты линейной и угловой скорости. Камерный reference с отслеживаемой
базой тоже учитывает перемещение/вращение; без базы используется исходная
высота. Arms намеренно исключает ноги, корпус и движение базы.

[Все найденные несоответствия, исправления и оставшиеся ограничения](../WBC_REFERENCE_AUDIT.md).

## Проверки без робота

```bash
deploy/g1/build/g1_policy_check
ctest --test-dir deploy/g1/build --output-on-failure
./uv run python -m unittest discover -s deploy/tests -v
```

`g1_policy_check` измеряет инференс на синтетических входах, без DDS.
Тесты используют настоящий ONNX Runtime и замкнутую динамику MuJoCo, проверяют
Idle, ходьбу/остановку, руки перед собой и пропадание/возврат трекинга.
Отдельные регрессии проверяют FixStand при наклоне 81°, линейность `ts/qs`,
точные исходные `kp/kd`, флаги наклона, сброс VQ и ограничение момента WBC.
Отрицательная проверка отдельно воспроизводит потерю баланса на чистом PD.
Это короткие регрессии, а не подтверждение всех движений и физического G1.
Нативный запуск на ARM64 здесь не проверен.

`sim/scene.xml` — плоская тестовая сцена с G1 из Unitree MuJoCo; лицензия и
исходная физическая модель сохранены. Эта сцена не меняет внешний unitree_mujoco.
